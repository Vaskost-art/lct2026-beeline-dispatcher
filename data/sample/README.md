# Эталонный тестовый набор данных

Собран скриптом `scripts/make_sample.py` из обезличенной синтетической
выгрузки организаторов по району Восток за 17.08.2026. Окна, адреса и состав
работ настоящие. Поля, которых в выгрузке нет (длительность, навыки,
транспорт, смены, стартовая точка, оборудование), достроены по допущениям из
README, раздел «Что мы достроили за данные»; те же допущения показаны в
интерфейсе в окне «Как считаем».

| Файл | Что внутри |
| --- | --- |
| `dataset.json` | Заявки и исполнители, плюс событие перепланирования в поле `events` |
| `event.json` | То же событие отдельным файлом |
| `expected_result.json` | Пример ожидаемого формата результата по ТЗ п. 2.4.2 |

Набор загружается в интерфейс через меню: «Загрузить свой набор». Событие из
файла в интерфейс само не подставляется: его вводят в форме «Событие в
течение дня» либо передают в ручку `/api/replan`.

## Соответствие требованиям ТЗ п. 6

| Требование | Факт |
| --- | --- |
| 10-15 инженеров | 10 |
| Не более 100 заявок | 66 |
| Все три навыка в заявках | подключения 37, локальные 21, аварийные 8 |
| Разные комбинации навыков у исполнителей | 4 комбинации: от одного навыка до всех трёх |
| Все типы транспорта | автомобиль 4, общественный транспорт 4, пешеход 1, велосипед 1 |
| Пересекающиеся временные окна | 356 пересекающихся пар |
| Конфликт, где последовательное распределение хуже | базовый вариант 29/66 заявок и 6,44 км на заявку против 66/66 и 2,73 км у оптимизатора |

Расчётный минимум бригад для Востока восемь, поэтому набор берёт нижнюю
границу ТЗ, десять. Велосипеда в долях транспорта модели нет, и одна бригада
без машины пересажена на него, чтобы в наборе встретились все типы.

Проверка выполняется самим скриптом: `python scripts/make_sample.py`
печатает этот список и завершается с ненулевым кодом, если хоть один пункт не
выполнен. Поиск оптимизатора останавливается по числу перебранных решений, а
не по секундам, поэтому результат повторяется от запуска к запуску.

## Единицы измерения

| Величина | Единица | Пример |
| --- | --- | --- |
| Время | `ЧЧ:ММ` | `"window_start": "10:00"` |
| Длительность работ, время в пути | минуты | `"duration_min": 90` |
| Расстояние, пробег | километры | `"пробег_км": 12.4` |
| Координаты | широта/долгота, WGS84 | `"lat": 55.7043, "lon": 37.7386` |

## Поля заявки

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `id` | да | Номер заявки, уникален в наборе |
| `lat`, `lon` | да | Координаты точки работ |
| `duration_min` | да | Длительность работ на адресе в минутах, больше нуля |
| `window_start`, `window_end` | да | Границы временного окна; конец строго позже начала |
| `required_skill` | да | Значение из справочника навыков |
| `priority` | нет | `Обычная`, `Повышенная` или `Срочная`, по умолчанию обычная |
| `required_vehicle` | нет | Значение из справочника транспорта либо `null`, если ограничения нет |
| `equipment` | нет | Список устройств, которые бригада везёт клиенту: `Роутер`, `ТВ-приставка`, `Умная колонка` |
| `address`, `district` | нет | Для отображения и объяснений |
| `type_bk`, `type_hd` | нет | Исходные типы работ из выгрузки, для справки |
| `geocode_precision` | нет | `exact` - координата из геокодера, `approx_district` - центр района, `provided` - пришла в наборе как есть, `manual` - точку задал диспетчер. Влияет только на предупреждение в интерфейсе |

## Поля исполнителя

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `id` | да | Идентификатор, уникален в наборе |
| `lat`, `lon` | да | Стартовая точка маршрута |
| `shift_start`, `shift_end` | да | Границы смены; конец строго позже начала |
| `break_min` | нет | Перерыв на обед в минутах, по умолчанию 0. Вычитается из ёмкости смены: время обеда в маршруте не фиксируется |
| `skills` | да | От одного до трёх значений из справочника навыков |
| `vehicle` | нет | Значение из справочника транспорта, по умолчанию автомобиль |
| `name`, `start_address` | нет | Для отображения |
| `resume_after`, `resume_at`, `en_route_to` | нет | Служебные поля дня, изменённого событием: откуда и когда бригада снова свободна. В утреннем наборе пустые |

## Поля события перепланирования

| Поле | Описание |
| --- | --- |
| `kind` | `urgent_order` (новая заявка), `cancel_order`, `engineer_unavailable` либо `engineer_delayed` |
| `at` | Время события, `ЧЧ:ММ` |
| `order_id` | Для отмены заявки |
| `engineer_id` | Для недоступности исполнителя и для его задержки |
| `delay_min` | Для задержки: на сколько минут сдвигается остаток маршрута |
| `new_order` | Для новой заявки: полный набор полей заявки |

## Справочники

**Навык:** локальные работы; работы на подключение и дозаказы; аварийные работы.

**Тип транспортного средства:** автомобиль; пешеход; велосипед; общественный транспорт.

**Приоритет заявки:** обычная; повышенная; срочная. В ТЗ приоритетов два;
третий, «Повышенная», для подключений, добавлен по порядку, заданному
постановщиком: авария, подключение, остальное.

Значения вне справочников отклоняются при загрузке с явным сообщением о том,
какое поле не прошло и какие значения допустимы.
